[✓] Step 2 — Design rebloom data
    - Inspected the existing blooms database table.
    - Decided to keep the existing blooms table unchanged.
    - Decided to use a separate reblooms table to represent the
      relationship between a bloom and the user who rebloomed it.
    - The reblooms table will store the original bloom ID, the
      reblooming user's ID, and the rebloom timestamp.
    - The rebloom count will be calculated from rebloom records
      rather than stored separately.
    - A bloom with no reblooms will not display a rebloom count.
    - The same user should not be able to rebloom the same bloom
      more than once.
    - The UI must distinguish the original author from the user
      who rebloomed the bloom.
    - A rebloom should have its own timestamp so it can enter the
      timeline as a new activity while preserving the original
      bloom's timestamp and author.
